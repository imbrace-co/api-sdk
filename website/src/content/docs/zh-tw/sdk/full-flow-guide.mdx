2. **建立 AI agent**

   `workflow_name` 在您的組織內必須是唯一的。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const agent = await client.chatAi.createAiAgent({
         name: "Support Bot",
         workflow_name: "support_bot_v1",
         description: "Handles tier-1 customer support queries",
         instructions: "You are a helpful support agent. Be concise and friendly.",
         provider_id: "system",   // 使用組織的預設 LLM 提供者
         model_id: "Default",     // 路由到組織配置的預設模型
         streaming: true,         // 發出 text-delta SSE 事件（見下方 Aside）
       })

       const aiAgentId = agent.id  // UUID — 所有後續呼叫使用此 ID
       console.log("AI agent created:", aiAgentId)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       agent = client.chat_ai.create_ai_agent({
           "name": "Support Bot",
           "workflow_name": "support_bot_v1",
           "description": "Handles tier-1 customer support queries",
           "instructions": "You are a helpful support agent. Be concise and friendly.",
           "provider_id": "system",   # 使用組織的預設 LLM 提供者
           "model_id": "Default",     # 路由到組織配置的預設模型
           "streaming": True,         # 發出 text-delta SSE 事件（見下方 Aside）
       })

       ai_agent_id = agent["id"]
       print("AI agent created:", ai_agent_id)
       ```
     </TabItem>
   </Tabs>

   `provider_id` 和 `model_id` 是可選的 — SDK 在省略時會自動填入 `{ provider_id: "system", model_id: "Default" }`。`"Default"` 路由到組織配置的系統預設模型，是跨組織通用的選擇。顯式傳入即可覆寫：`provider_id: "<uuid>"` 指定自訂 LLM 提供者，或 `model_id: "gpt-4o"` 等 — 但具體模型名稱只在該組織的 `system` 提供者實際公開該模型時才有效。在硬編碼前，使用 `client.ai.listModels()`（TypeScript）/ `client.ai.list_models()`（Python）列出組織的可用模型。

   <Aside type="caution" title="聊天 UI 請一律傳入 streaming: true">
     新建立的代理在伺服器端預設為 **`streaming: false`**。在此預設下，`streamChat` 會以單一 `text/plain` 回應傳回完整回覆 — 沒有任何 `text-delta` 事件 — 因此 `streamChatText` 輔助方法（以及任何其他 SSE 解析器）會產出**零個片段**，聊天 UI 也就什麼都不顯示。在建立時傳入 `streaming: true`，伺服器便會發出 `streamChatText` 設計用來解析的 Vercel-AI-SDK UI-Message-Stream（`Content-Type: text/event-stream`）。您之後也可以透過 `updateAiAgent(id, { streaming: true })` 切換。
   </Aside>


3. **使用 AI agent 串流聊天回應**

   使用 `streamChatText` / `stream_chat_text` — 它包裝了 `streamChat`，會解析 SSE 事件串流並逐一產出純文字片段。前提是代理以 `streaming: true` 建立（見步驟 2 的 Aside）。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       for await (const chunk of client.aiAgent.streamChatText({
         assistant_id: aiAgentId,
         messages: [{ role: "user", content: "How do I reset my password?" }],
         // id 是連線 UUID — 重複使用以保持對話歷史記錄。
         // 如果省略，每次呼叫會自動產生新的 UUID。
       })) {
         process.stdout.write(chunk)
       }
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       for chunk in client.ai_agent.stream_chat_text({
           "assistant_id": ai_agent_id,
           "messages": [{"role": "user", "content": "How do I reset my password?"}],
           # id 是連線 UUID — 重複使用以保持對話歷史記錄。
           # 如果省略，每次呼叫會自動產生新的 UUID。
       }):
           print(chunk, end="", flush=True)
       ```
     </TabItem>
   </Tabs>

   <Aside type="tip" title="使用的是非串流代理？">
     如果代理設定為 `streaming: false`，伺服器會以單一 `text/plain` 回應傳回完整回覆 — 沒有可供 `streamChatText` 解析的 `text-delta` 事件，因此它不會產出任何內容。下方的模式會依 `Content-Type` 分流，同時處理兩種格式：

     <Tabs syncKey="lang">
       <TabItem label="TypeScript">
         ```typescript
         const res = await client.aiAgent.streamChat({
           assistant_id: aiAgentId,
           messages: [{ role: "user", content: "How do I reset my password?" }],
         })
         if (!res.ok) throw new Error(`HTTP ${res.status}: ${await res.text()}`)

         if ((res.headers.get("content-type") ?? "").includes("text/event-stream")) {
           // 串流代理 — 透過 SDK 輔助方法重新解析
           for await (const chunk of client.aiAgent.streamChatText({ /* 相同的 body */ })) {
             process.stdout.write(chunk)
           }
         } else {
           process.stdout.write(await res.text())   // 非串流代理
         }
         ```
       </TabItem>
       <TabItem label="Python">
         ```python
         res = client.ai_agent.stream_chat({
             "assistant_id": ai_agent_id,
             "messages": [{"role": "user", "content": "How do I reset my password?"}],
         })
         res.raise_for_status()

         if "text/event-stream" in res.headers.get("content-type", ""):
             for chunk in client.ai_agent.stream_chat_text({ "assistant_id": ai_agent_id, "messages": [...] }):
                 print(chunk, end="", flush=True)
         else:
             print(res.text)
         ```
       </TabItem>
     </Tabs>
   </Aside>

4. **維護對話歷史記錄（連線 ID）**

   在多次呼叫中傳遞相同的 `id`（必須是 UUID）以保持上下文：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       import { randomUUID } from "crypto"

       const sessionId = randomUUID()

       // 第一則訊息
       await client.aiAgent.streamChat({
         assistant_id: aiAgentId,
         id: sessionId,
         messages: [{ role: "user", content: "What's your refund policy?" }],
       })

       // 後續 — 相同連線，AI agent 記住上下文
       await client.aiAgent.streamChat({
         assistant_id: aiAgentId,
         id: sessionId,
         messages: [{ role: "user", content: "How long does it take?" }],
       })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       import uuid

       session_id = str(uuid.uuid4())

       # 第一則訊息
       client.ai_agent.stream_chat({
           "assistant_id": ai_agent_id,
           "id": session_id,
           "messages": [{"role": "user", "content": "What's your refund policy?"}],
       })

       # 後續 — 相同連線，AI agent 記住上下文
       client.ai_agent.stream_chat({
           "assistant_id": ai_agent_id,
           "id": session_id,
           "messages": [{"role": "user", "content": "How long does it take?"}],
       })
       ```
     </TabItem>
   </Tabs>

</Steps>

## 2. 建立工作流程並繫結至 AI Agent

<Steps>

1. **取得您的專案 ID**

   從 Imbrace Dashboard → Workflows 複製您的 Project ID；若您的組織已有流程，也可以透過程式解析：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 選項 A — 從 Dashboard 硬編碼（建議新組織使用）
       const projectId = "your_project_id"

       // 選項 B — 從現有流程解析（若組織尚無任何流程會拋出錯誤）
       const projectId = await client.workflows.resolveProjectId()
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       # 選項 A — 從 Dashboard 硬編碼（建議新組織使用）
       project_id = "your_project_id"

       # 選項 B — 從現有流程解析（若組織尚無任何流程會拋出錯誤）
       project_id = client.workflows.resolve_project_id()
       ```
     </TabItem>
   </Tabs>

2. **建立新流程**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const flow = await client.workflows.createFlow({
         displayName: "CRM Update on New Lead",
         projectId,
       })
       console.log("Flow created:", flow.id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       flow = client.workflows.create_flow(
           display_name="CRM Update on New Lead",
           project_id=project_id,
       )
       print("Flow created:", flow["id"])
       ```
     </TabItem>
   </Tabs>

3. **新增 Webhook 觸發條件並發佈流程**

   新建立的流程處於**草稿**狀態且沒有觸發條件 — Webhook URL 還不存在，因此 `triggerFlow` 會回傳 404。新增 Webhook 元件作為觸發條件，然後發佈：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 將 Webhook 元件設為流程的觸發條件
       await client.workflows.applyFlowOperation(flow.id, {
         type: "UPDATE_TRIGGER",
         request: {
           name: "trigger",
           type: "PIECE_TRIGGER",
           valid: true,
           displayName: "Webhook",
           settings: {
             pieceName: "@activepieces/piece-webhook",
             pieceVersion: "0.1.24",
             triggerName: "catch_webhook",
             input: { authType: "none" },
             propertySettings: {},
           },
         },
       })

       // 發佈 — 流程狀態從 DISABLED 轉為 ENABLED，Webhook URL 生效
       await client.workflows.applyFlowOperation(flow.id, {
         type: "LOCK_AND_PUBLISH",
         request: {},
       })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       # 將 Webhook 元件設為流程的觸發條件
       client.workflows.apply_flow_operation(flow["id"], {
           "type": "UPDATE_TRIGGER",
           "request": {
               "name": "trigger",
               "type": "PIECE_TRIGGER",
               "valid": True,
               "displayName": "Webhook",
               "settings": {
                   "pieceName": "@activepieces/piece-webhook",
                   "pieceVersion": "0.1.24",
                   "triggerName": "catch_webhook",
                   "input": {"authType": "none"},
                   "propertySettings": {},
               },
           },
       })

       # 發佈 — DISABLED → ENABLED，Webhook URL 生效
       client.workflows.apply_flow_operation(flow["id"], {
           "type": "LOCK_AND_PUBLISH",
           "request": {},
       })
       ```
     </TabItem>
   </Tabs>

4. **使用酬載手動觸發流程**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 觸發後即忘（非同步）
       await client.workflows.triggerFlow(flow.id, {
         contact_name: "Jane Smith",
         email: "jane@example.com",
       })

       // 同步觸發 — 要讓它實際回傳資料而不會逾時，
       // 流程需要透過 applyFlowOperation ADD_ACTION 新增「回傳回應」動作
       // （否則閘道會等待 30 秒回應然後放棄）。
       const result = await client.workflows.triggerFlowSync(flow.id, {
         contact_name: "Jane Smith",
         email: "jane@example.com",
       })
       console.log("Flow result:", result)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       # 觸發後即忘（非同步）
       client.workflows.trigger_flow(flow["id"], {
           "contact_name": "Jane Smith",
           "email": "jane@example.com",
       })

       # 同步觸發 — 要讓它實際回傳資料而不會逾時，
       # 流程需要透過 apply_flow_operation ADD_ACTION 新增「回傳回應」動作
       # （否則閘道會等待 30 秒然後放棄）。
       result = client.workflows.trigger_flow_sync(flow["id"], {
           "contact_name": "Jane Smith",
           "email": "jane@example.com",
       })
       print("Flow result:", result)
       ```
     </TabItem>
   </Tabs>

5. **將流程繫結至您的 AI agent**

   在 Imbrace 儀表板中開啟您的 AI agent，前往**工具 → 工作流程**，然後附加流程。AI agent 將能夠在對話中適當時觸發它。

   或者，更新 AI agent 以依名稱參考工作流程：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       await client.chatAi.updateAiAgent(aiAgentId, {
         name: "Support Bot",
         workflow_name: "support_bot_v1",
         workflow_function_call: [{ flow_id: flow.id, description: "Update CRM on new lead" }],
       })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       client.chat_ai.update_ai_agent(ai_agent_id, {
           "name": "Support Bot",
           "workflow_name": "support_bot_v1",
           "workflow_function_call": [
               {"flow_id": flow["id"], "description": "Update CRM on new lead"}
           ],
       })
       ```
     </TabItem>
   </Tabs>

6. **檢查執行歷史記錄**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const { data: runs } = await client.workflows.listRuns({
         flowId: flow.id,
         limit: 10,
       })
       for (const run of runs) {
         console.log(run.id, run.status, run.startTime)
       }
       ```
     </TabItem>
     <TabItem label="Python">
       ```python

       for run in res.get("data", []):
           print(run["id"], run.get("status"), run.get("startTime"))
       ```
     </TabItem>
   </Tabs>

</Steps>

## 3. 管理知識中心並附加至 AI Agent

知識中心檔案和資料夾存在於 **data-board** 服務（`client.boards`）中。資料夾的 `_id` 就是您傳遞給 AI agent 作為其知識來源的內容。

<Steps>

1. **建立資料夾**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const folder = await client.boards.createFolder({
         name: "Product Documentation",
         organization_id: process.env.IMBRACE_ORGANIZATION_ID,
         parent_id: "root",
       })
       console.log("Folder ID:", folder._id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       folder = client.boards.create_folder({
           "name": "Product Documentation",
           "organization_id": os.environ.get("IMBRACE_ORGANIZATION_ID"),
           "parent_id": "root",
       })
       print("Folder ID:", folder["_id"])
       ```
     </TabItem>
   </Tabs>

2. **上傳檔案至資料夾**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       import { readFileSync } from "fs"

       const fileBuffer = readFileSync("./docs/faq.pdf")
       const formData = new FormData()
       formData.append("file", new Blob([fileBuffer], { type: "application/pdf" }), "faq.pdf")
       formData.append("folder_id", folder._id)
       formData.append("organization_id", process.env.IMBRACE_ORGANIZATION_ID ?? "")

       const uploaded = await client.boards.uploadFile(formData)
       console.log("File uploaded:", uploaded.file_id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       from pathlib import Path

       path = Path("./docs/faq.pdf")
       files = {
           "file": (path.name, path.read_bytes(), "application/pdf"),
           "folder_id": (None, folder["_id"]),
           "organization_id": (None, os.environ.get("IMBRACE_ORGANIZATION_ID")),
       }
       uploaded = client.boards.upload_file(files)
       print("File uploaded:", uploaded.get("file_id") or uploaded.get("_id"))
       ```
     </TabItem>
   </Tabs>

3. **將資料夾附加至 AI agent**

   在 `folder_ids` 中傳遞資料夾 `_id` — AI agent 從該資料夾中的每個檔案檢索。使用 `board_ids` 來附加 CRM data-board（其項目成為知識來源 — 請參閱[資源 → Boards 與項目](/sdk/resources/#boards--items--clientboards)）。舊的 `knowledge_hubs` 欄位已棄用。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       await client.chatAi.updateAiAgent(aiAgentId, {
         name: "Support Bot",
         workflow_name: "support_bot_v1",
         folder_ids: [folder._id],
         // board_ids: [boardId],  // 可選：也附加 CRM data-board
       })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       client.chat_ai.update_ai_agent(ai_agent_id, {
           "name": "Support Bot",
           "workflow_name": "support_bot_v1",
           "folder_ids": [folder["_id"]],
           # "board_ids": [board_id],  # 可選：也附加 CRM data-board
       })
       ```
     </TabItem>
   </Tabs>

4. **檢查和管理資料夾與檔案**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 搜尋資料夾
       const folders = await client.boards.searchFolders({ q: "Product" })

       // 取得資料夾內容
       const contents = await client.boards.getFolderContents(folder._id)
       console.log("Files:", contents.files?.length)

       // 重新命名資料夾
       await client.boards.updateFolder(folder._id, { name: "Product Docs v2" })

       // 搜尋資料夾中的檔案
       const files = await client.boards.searchFiles({ folderId: folder._id })

       // 刪除資料夾
       await client.boards.deleteFolders({ ids: [folder._id] })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       # 搜尋資料夾
       folders = client.boards.search_folders(q="Product")

       # 取得資料夾內容
       contents = client.boards.get_folder_contents(folder["_id"])
       print("Files:", len(contents.get("files") or []))

       # 重新命名資料夾
       client.boards.update_folder(folder["_id"], {"name": "Product Docs v2"})

       # 搜尋資料夾中的檔案
       files = client.boards.search_files(folder_id=folder["_id"])

       # 刪除資料夾
       client.boards.delete_folders([folder["_id"]])
       ```
     </TabItem>
   </Tabs>

</Steps>

## 4. 管理 Data Boards 與項目（CRM 管道）

<Steps>

1. **建立 Board**

   Board 就是一個 CRM 管道 — 潛在客戶、交易、任務或任何結構化資料。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const board = await client.boards.create({
         name: "Sales Pipeline",
         description: "Track all active deals",
       })
       console.log("Board ID:", board._id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       board = client.boards.create(
           name="Sales Pipeline",
           description="Track all active deals",
       )
       print("Board ID:", board["_id"])
       ```
     </TabItem>
   </Tabs>

2. **新增自訂欄位**

   欄位類型有 `ShortText`、`LongText`、`Number`、`Dropdown`、`Date`、`Checkbox` 等。`createField` 會回傳新建立的欄位。若要檢視 board 上的所有欄位，請另外擷取該 board。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       await client.boards.createField(board._id, {
         name: "Company",
         type: "ShortText",
       })

       // Board 會自動建立識別欄位 — 擷取 board 以查看所有欄位
       const boardWithFields = await client.boards.get(board._id) as any
       const identifierField = boardWithFields.fields?.find((f: any) => f.is_identifier)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       client.boards.create_field(board["_id"], {
           "name": "Company",
           "type": "ShortText",
       })

       # 擷取 board 以查看所有欄位（包括自動建立的識別欄位）
       board_with_fields = client.boards.get(board["_id"])
       identifier_field = next(f for f in board_with_fields.get("fields", []) if f.get("is_identifier"))
       ```
     </TabItem>
   </Tabs>

3. **建立 board 項目（記錄）**

   項目使用 `{ fields: [{ board_field_id, value }] }` 格式：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const item = await client.boards.createItem(board._id, {
         fields: [
           { board_field_id: identifierField._id, value: "Acme Corp" },
         ],
       })
       console.log("Item ID:", item._id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       item = client.boards.create_item(board["_id"], {
           "fields": [
               {"board_field_id": identifier_field["_id"], "value": "Acme Corp"},
           ],
       })
       print("Item ID:", item["_id"])
       ```
     </TabItem>
   </Tabs>

         limit: 10,

       await client.boards.updateItem(board._id, item._id, {
