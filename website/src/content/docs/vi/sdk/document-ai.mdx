import { Tabs, TabItem } from "@astrojs/starlight/components";

Document AI sử dụng vision models (ví dụ: GPT-4o) để trích xuất dữ liệu có cấu trúc từ PDF và hình ảnh — hóa đơn, biểu mẫu, biên lai, hợp đồng, hoặc bất kỳ tài liệu nào có văn bản nhìn thấy được.

SDK cung cấp bốn namespace:
- **`client.dociq`** — upload tài liệu lên DocIQ: DocIQ chọn Document Model phù hợp cho từng tài liệu, trích xuất và ghi một bản ghi lên board của model đó
- **`client.chatAi` / `client.chat_ai`** — xử lý tài liệu trực tiếp và liệt kê model
- **`client.documentModels` / `client.document_models`** — Document Model của DocIQ: các trường cần trích xuất, board nhận kết quả, danh mục và cài đặt trích xuất
- **`client.documentAi` / `client.document_ai`** — xử lý tài liệu dựa trên agent, job hàng đợi, CRUD agent và điều phối đầu cuối

Khởi tạo client trước (xem [Cài đặt](/sdk/installation/) hoặc [Quick Start](/sdk/quick-start/)).

## `client.dociq` — Upload và trích xuất (DocIQ)

Đây là cách thường dùng để đưa tài liệu vào DocIQ. Upload file rồi gửi nó đi: DocIQ chọn Document Model phù hợp, trích xuất các trường và ghi một bản ghi lên board của model đó. Hãy thiết lập model trước bằng [`client.documentModels`](#clientdocumentmodels--document-models-dociq).

### Upload và gửi tài liệu

Upload bằng `client.boards.uploadBoardFile()`, rồi truyền `url` nhận được vào `ingest()`. Mỗi lần gọi nhận từ 1 đến 5 file và trả về ngay một submission cho mỗi file; việc đọc tài liệu chạy ở chế độ nền.

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const form = new FormData();
form.append("file", new Blob([pdfBytes], { type: "application/pdf" }), "invoice.pdf");
const { url } = await client.boards.uploadBoardFile(form);

const { submissions } = await client.dociq.ingest({
  files: [{ url, mime_type: "application/pdf", name: "invoice.pdf" }],
});
const submissionId = submissions[0].id;
```
</TabItem>
<TabItem label="Python">
```python
with open("invoice.pdf", "rb") as f:
    url = client.boards.upload_board_file({"file": ("invoice.pdf", f, "application/pdf")})["url"]

res = client.dociq.ingest([{"url": url, "mime_type": "application/pdf", "name": "invoice.pdf"}])
submission_id = res["submissions"][0]["id"]
```
</TabItem>
</Tabs>

| Tùy chọn | Kiểu | Ý nghĩa |
|---|---|---|
| `files` | `{ url, mime_type, name? }[]` | 1 đến 5 file. `url` là giá trị upload trả về, hoặc một URL tuyệt đối |
| `assistant_id` | string | Đọc bằng các model của DocIQ assistant này thay vì model mặc định |
| `source` | `{ channel?, conversation_id? }` | Nguồn của file khi không phải upload (ví dụ một kênh nhắn tin). Được lưu nguyên như bạn gửi |

Việc ghi lên board chạy dưới danh nghĩa người gọi, nên request phải mang theo một người dùng: lệnh gọi không có người dùng sẽ bị từ chối với lỗi 400. Tổ chức cần có tính năng Document Model.

### Theo dõi một submission

Một submission có hai trạng thái. `status` là việc đọc tài liệu: `pending`, `running`, rồi `succeeded`, `failed` hoặc `canceled`. `outcome` là việc ghi lên board: `saved`, `no_schema` (không có model phù hợp), `model_created`, `failed`, hoặc `pending` khi chưa chạy.

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
let sub = await client.dociq.getSubmission(submissionId);
while (sub.status === "pending" || sub.status === "running" || (sub.status === "succeeded" && sub.outcome === "pending")) {
  await new Promise(r => setTimeout(r, 5000));
  sub = await client.dociq.getSubmission(submissionId);
}

if (sub.outcome === "saved") {
  console.log(sub.documentModelName, sub.boardId, sub.boardItemId);
  console.log(sub.extractedData);  // bản ghi
  console.log(sub.extractedMeta);  // từng trường: độ tin cậy, trạng thái, vị trí đọc được
}
```
</TabItem>
<TabItem label="Python">
```python
import time

sub = client.dociq.get_submission(submission_id)
while sub["status"] in ("pending", "running") or (sub["status"] == "succeeded" and sub["outcome"] == "pending"):
    time.sleep(5)
    sub = client.dociq.get_submission(submission_id)

if sub["outcome"] == "saved":
    print(sub["documentModelName"], sub["boardId"], sub["boardItemId"])
    print(sub["extractedData"])  # bản ghi
    print(sub["extractedMeta"])  # từng trường: độ tin cậy, trạng thái, vị trí đọc được
```
</TabItem>
</Tabs>

Một file chứa nhiều tài liệu (ví dụ ba hóa đơn trong một PDF) sẽ được tách ra: `documents` liệt kê từng tài liệu kèm model và board riêng, còn `boardItemId` là bản ghi đầu tiên. Submission bị lỗi có `error` và `processLog`. `getSubmissionByFile()` tìm submission mới nhất theo File ID hiển thị trong bảng kết quả (ví dụ `INV-2026-001`).

## `client.documentModels` — Document Models (DocIQ)

Một Document Model liệt kê các trường cần trích xuất từ một loại tài liệu. Mỗi model có một board, và mỗi tài liệu được đọc bằng model đó trở thành một bản ghi trên board này. [`client.dociq`](#clientdociq--upload-and-extract-dociq) tự chọn model cho từng tài liệu; còn với `documentAi.process()` thì bạn truyền board vào `boardId`.

Mỗi model thuộc về một sản phẩm, chính là `type` của nó: `"DocumentAI"` (DocIQ, mặc định) hoặc `"Comms"` (CommsIQ). `type` được đặt khi tạo model và không bao giờ thay đổi.

### Tạo model và board của nó

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript

  name: "Invoice",
  attributes: [
    { name: "Invoice number", type: "ShortText" },
    { name: "Total", type: "Number" },
    { name: "Date", type: "Date" },
  ],
});

// Tạo model không tự tạo board: cần provision board.
const [{ board_id }] = await client.documentModels.provisionBoards({
  schemas: [{ schema_id: model.id, data_board_name: "Invoices" }],
});

const result = await client.documentAi.process({
  url: "https://example.com/invoice.pdf",
  organizationId: "org_xxx",
  modelName: "gpt-4o",
  boardId: board_id,
});
```
</TabItem>
<TabItem label="Python">
```python

        {"name": "Invoice number", "type": "ShortText"},
```

## Trích xuất qua hàng đợi và webhook

`client.documentAi.process()` và `client.chatAi.processDocument()` gọi cùng một endpoint. Server có thể đưa tài liệu vào hàng đợi thay vì trích xuất ngay; mặc định, PDF dài hơn 20 trang sẽ vào hàng đợi. Khi đó lệnh gọi trả về ngay (HTTP 202) với `job_id` và không có `data`.

- Truyền `sync: true` để luôn trích xuất ngay và nhận `data`.
- Truyền `sync: false` để luôn đưa vào hàng đợi.
- Theo dõi job bằng `getJob()`. Các trường đã trích xuất không nằm trong job: khi `status` là `done`, chúng nằm trên dòng board mà job trỏ tới, trong trường `RawResult`.

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const res = await client.documentAi.process({
  url: "https://example.com/contract.pdf",
  organizationId: "org_xxx",
  modelName: "gpt-4o",
  boardId: board_id,
});

if (res.job_id) {
  let job = await client.documentAi.getJob(res.job_id);
  while (job.status === "pending" || job.status === "in_progress") {
    await new Promise(r => setTimeout(r, 5000));
    job = await client.documentAi.getJob(res.job_id);
  }
  if (job.status === "done" && job.board_id && job.board_item_id) {
    const row = await client.boards.getItem(job.board_id, job.board_item_id);
  }
} else {
  console.log(res.data);
}
```
</TabItem>
<TabItem label="Python">
```python
import time

res = client.document_ai.process(
    url="https://example.com/contract.pdf",
    organization_id="org_xxx",
    model_name="gpt-4o",
    boardId=board_id,
)

if res.get("job_id"):
    job = client.document_ai.get_job(res["job_id"])
    while job["status"] in ("pending", "in_progress"):
        time.sleep(5)
        job = client.document_ai.get_job(res["job_id"])
    if job["status"] == "done":
        row = client.boards.get_item(job["board_id"], job["board_item_id"])
else:
    print(res["data"])
```
</TabItem>
</Tabs>

`status` của job là `pending`, `in_progress`, `done` hoặc `error`. Bản ghi job mặc định hết hạn sau một ngày, khi đó `getJob()` báo lỗi 404; dòng trên board vẫn còn.

Thay vì hỏi liên tục, hãy truyền `webhookUrl`. Server sẽ POST kết quả tới URL này khi trích xuất xong, dù thành công hay lỗi, xử lý ngay hay qua hàng đợi, kèm theo `meta` bạn đã gửi:

```json
{
  "event": "document_ai.completed",
  "status": "completed",
  "job_id": "…",
  "board_id": "…",
  "board_item_id": "…",
  "data": { },
  "meta": { "ref": "r1" },
  "error": null
}
```

`job_id` là `null` khi tài liệu được xử lý ngay. `status` là `"completed"` hoặc `"error"`.

## Độ tin cậy OCR

Với `enableOcrConfidence`, một engine OCR đọc tài liệu song song với vision model, và mỗi trường trích xuất được gắn thêm `{ value, box, confidence }`. `confidenceThreshold` (0–1) loại bỏ các trường có độ tin cậy thấp hơn. `ocrEngine` chọn engine: `"paddleocr-vl"` (chỉ văn bản), `"chandra"` (bố cục kèm khung) hoặc `"easyocr"` (khối văn bản kèm khung); bỏ trống thì server dùng engine mặc định.

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const result = await client.documentAi.process({
  url: "https://example.com/scan.png",
  organizationId: "org_xxx",
  modelName: "gpt-4o",
  boardId: board_id,
  sync: true,
  enableOcrConfidence: true,
  confidenceThreshold: 0.6,
  ocrEngine: "easyocr",
});
```
</TabItem>
<TabItem label="Python">
