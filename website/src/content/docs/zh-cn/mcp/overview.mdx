把你的 AI 工具 — Claude Code、Cursor、Codex、Claude Desktop 等 — 连接到 Imbrace，它就能直接操作你的 Imbrace 数据：列出 CRM 面板、读取对话、查看工作流运行等。

<Aside type="tip">
正在使用 Claude Code、ChatGPT 或 Codex？[Agent Toolkit](/zh-cn/mcp/agent-toolkit/) 插件会教你的代理使用 iMBrace SDK、CLI 和 MCP 服务器，并在 Claude Code 中自动为你添加此服务器 — 在你的环境已启用时支持 OAuth 登录。在 claude.ai、Claude Desktop 或移动应用中，已启用 OAuth 的网关（生产环境）可以添加为[自定义连接器](/zh-cn/mcp/agent-toolkit/#custom-connector)，无需 API key。
</Aside>

你只需要两样东西：

- **一个 URL** — Imbrace 网关在 `/mcp` 托管了一个 [Model Context Protocol](https://modelcontextprotocol.io) 服务器，无需安装或自行运行任何东西。
- **一个 API key** — 作为 Bearer token 发送。代理只能看到你的组织和角色允许的内容，不会更多。

### 第 1 步 — 获取 API key

在 Imbrace Dashboard 生成外部 token（参见[获取 API Key](/zh-cn/guides/api-key/)），形如 `api_...`。

### 第 2 步 — 连接你的工具

在下方选择你的工具并粘贴配置。示例使用 **sandbox** 网关 — 请替换为你所在环境的网关主机名。

<Tabs>
<TabItem label="Claude Code">

一条命令：

```bash
claude mcp add --transport http imbrace "https://app-gateway.sandbox.imbrace.co/mcp" \
  --header "Authorization: Bearer api_xxx..."
```

</TabItem>
<TabItem label="Cursor">

添加到项目中的 `.cursor/mcp.json` — 或 `~/.cursor/mcp.json` 以全局启用：

```json
{
  "mcpServers": {
    "imbrace": {
      "url": "https://app-gateway.sandbox.imbrace.co/mcp",
      "headers": { "Authorization": "Bearer api_xxx..." }
    }
  }
}
```

</TabItem>
<TabItem label="Codex CLI">

添加到 `~/.codex/config.toml`（支持 HTTP MCP 的新版 Codex）：

```toml
[mcp_servers.imbrace]
url = "https://app-gateway.sandbox.imbrace.co/mcp"
bearer_token = "api_xxx..."
```

旧版 Codex 不支持 HTTP 时，通过 `mcp-remote` 桥接：

```toml
[mcp_servers.imbrace]
command = "npx"
args = ["-y", "mcp-remote", "https://app-gateway.sandbox.imbrace.co/mcp", "--header", "Authorization: Bearer api_xxx..."]
```

</TabItem>
<TabItem label="Claude Desktop">

对于已启用 OAuth 的网关（生产环境），无需 key 或配置文件：改为添加[自定义连接器](/zh-cn/mcp/agent-toolkit/#custom-connector)。使用 API key 时：

Claude Desktop 只启动本地服务器，因此用 `mcp-remote` 桥接 URL。在 **Settings → Developer → Edit Config** 中，添加到 `claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "imbrace": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote",
        "https://app-gateway.sandbox.imbrace.co/mcp",
        "--header", "Authorization: Bearer api_xxx..."
      ]
    }
  }
}
```

</TabItem>
<TabItem label="其他客户端">

任何接受 URL 加请求头的 MCP 客户端都使用标准形式：

```json
{
  "mcpServers": {
    "imbrace": {
      "url": "https://app-gateway.sandbox.imbrace.co/mcp",
      "headers": { "Authorization": "Bearer api_xxx..." }
    }
  }
}
```

如果客户端只支持本地（stdio）服务器，用以下方式桥接：

```bash
npx -y mcp-remote "https://app-gateway.sandbox.imbrace.co/mcp" \
  --header "Authorization: Bearer api_xxx..."
```

</TabItem>
</Tabs>

### 第 3 步 — 试一试

问你的代理，例如*"列出我的 Imbrace 面板"*或*"看看最新的对话"*。它会自动选用 `listBoards`、`listConversations`、`listFlows` 等工具。

<a id="vibe-code"></a>

### 在 iMBrace 上构建应用（vibe code）

连接之后，你的代理已经知道 vibe code 指南在哪里：服务器会把它指向 [`/skill.md`](https://engineer.imbrace.co/skill.md)。直接说出你想要的，例如*"给我的水疗店做一个预约页面，并在 iMBrace 上运行"*，代理就会获取指南并照着做。无需复制提示词。

如果想明确地开始，使用服务器的 **`vibe-code`** 提示（可选参数：`idea`，应用要做什么）：

- **Claude Code：** 输入 `/` 并选择 `vibe-code`。它显示为 `/mcp__<服务器名>__vibe-code`，例如 `/mcp__imbrace__vibe-code`。
- **其他支持提示的 MCP 客户端** 会在该服务器的提示列表中列出它。

使用 [Agent Toolkit](/zh-cn/mcp/agent-toolkit/) 插件时，其 `imbrace-vibe-code` 技能也能做到同样的事。Vibe code 需要安装 CLI 并在终端中部署，所以请使用编码代理（Claude Code、Cursor、Codex）；在 claude.ai 上代理可以阅读指南，但无法执行这些步骤。

### 默认只读

默认情况下代理**只能看、不能改** — 只暴露读取工具。要开放更多权限，在所配置的 URL 上添加查询参数：

| 添加到 URL | 效果 |
|---|---|
| `?allowWrite=1` | 代理还可以创建和修改数据 |
| `?allowDestructive=1` | 代理还可以删除数据（包含 write） |
| `?services=dataBoard,workflow` | 收窄：仅这些服务 |
| `?tags=boards,records` | 收窄：仅这些主题 |

示例 — 仅数据面板，带写入权限：

```
https://app-gateway.sandbox.imbrace.co/mcp?services=dataBoard&allowWrite=1
```

服务：`dataBoard`、`channel`、`platform`、`marketplace`、`workflow`、`aiAgent`。代理调用未启用的工具会收到明确错误 — 不会静默失败。

返回结果会保持在代理可读的长度：`listFlows` 和 `listPieces` 返回每一项的摘要（完整定义见 `getFlow` / `getPiece`）；一次返回不下的长列表只包含前面的条目，并附带 `_truncated: { returned, total }` — 请用工具的筛选或分页参数缩小范围。

### 工作原理

每次工具调用都会带着**你的** token 经网关的正常 API 路由重放，因此组织范围、权限与 license 检查与你亲自调用 API 完全一致。工具即精选的 `agent-tools` 操作集，与 SDK 的 [`client.api`](/sdk/overview/#the-full-api-surface--clientapi-typescript) 表面同源。端点是基于 HTTP `POST` 的无状态 JSON-RPC — 无需管理会话。

### 不用 MCP？统一 OpenAPI

使用 OpenAPI 工具规范而非 MCP 的平台（如 Open WebUI）可以指向 `GET /agent-tools/openapi.json`（同样的 `Authorization` 头）：所有服务的 agent-tools 合并为**一份** spec，支持同样的 `?services=` / `?tags=` 过滤 — 一个工具服务器而不是五个。把基础 URL 与操作路径简单拼接的执行器（请求成 `/agent-tools/<op-path>`）也能兼容：网关会去掉前缀并带你的凭证重放请求。

### 本地替代方案 — CLI

想要本地 stdio 服务器（凭证来自 CLI profile，无需配置 URL）？CLI 内置同一套工具注册表：[`imbrace mcp`](/zh-cn/cli/commands/#mcp-server)。
