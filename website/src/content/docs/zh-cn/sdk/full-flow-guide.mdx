2. **创建 AI 代理**

   `workflow_name` 在你的组织内必须是唯一的。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const agent = await client.chatAi.createAiAgent({
         name: "Support Bot",
         workflow_name: "support_bot_v1",
         description: "Handles tier-1 customer support queries",
         instructions: "You are a helpful support agent. Be concise and friendly.",
         provider_id: "system",   // 使用组织的默认 LLM 提供商
         model_id: "Default",     // 路由到组织配置的默认模型
         streaming: true,         // 发出 text-delta SSE 事件（见下方提示框）
       })

       const aiAgentId = agent.id  // UUID — 用于所有后续调用
       console.log("AI agent created:", aiAgentId)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       agent = client.chat_ai.create_ai_agent({
           "name": "Support Bot",
           "workflow_name": "support_bot_v1",
           "description": "Handles tier-1 customer support queries",
           "instructions": "You are a helpful support agent. Be concise and friendly.",
           "provider_id": "system",   # 使用组织的默认 LLM 提供商
           "model_id": "Default",     # 路由到组织配置的默认模型
           "streaming": True,         # 发出 text-delta SSE 事件（见下方提示框）
       })

       ai_agent_id = agent["id"]
       print("AI agent created:", ai_agent_id)
       ```
     </TabItem>
   </Tabs>

   `provider_id` 和 `model_id` 是可选项 — 省略时 SDK 自动填充 `{ provider_id: "system", model_id: "Default" }`。`"Default"` 路由到组织配置的系统默认模型，是跨组织通用的选择。需要覆盖时显式传入：`provider_id: "<uuid>"` 用于指定自定义 LLM 提供商，或 `model_id: "gpt-4o"` 等 — 但具体模型名称只在该组织的 `system` 提供商实际公开它时才有效。在硬编码前，使用 `client.ai.listModels()`（TypeScript）/ `client.ai.list_models()`（Python）列出组织的可用模型。

   <Aside type="caution" title="聊天 UI 请始终传入 streaming: true">
     新创建的代理在服务器端默认为 **`streaming: false`**。在该默认值下，`streamChat` 会以单个 `text/plain` 响应返回完整回复 — 没有 `text-delta` 事件 — 因此 `streamChatText` 辅助方法（以及任何其他 SSE 解析器）会产出 **0 个 chunk**，聊天 UI 什么也不显示。在创建时传入 `streaming: true`，服务器就会发出 Vercel-AI-SDK UI-Message-Stream（`Content-Type: text/event-stream`），这正是 `streamChatText` 设计用来解析的格式。你也可以稍后通过 `updateAiAgent(id, { streaming: true })` 修改。
   </Aside>


3. **使用 AI 代理流式聊天**

   使用 `streamChatText` / `stream_chat_text` — 它封装了 `streamChat`，解析 SSE 事件流，并逐个产出纯文本 chunk。前提是代理在创建时设置了 `streaming: true`（参见步骤 2 中的提示框）。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       for await (const chunk of client.aiAgent.streamChatText({
         assistant_id: aiAgentId,
         messages: [{ role: "user", content: "How do I reset my password?" }],
         // id 是会话 UUID — 重复使用以保持对话历史。
         // 如果省略，每次调用会自动生成新的 UUID。
       })) {
         process.stdout.write(chunk)
       }
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       for chunk in client.ai_agent.stream_chat_text({
           "assistant_id": ai_agent_id,
           "messages": [{"role": "user", "content": "How do I reset my password?"}],
           # id 是会话 UUID — 重复使用以保持对话历史。
           # 如果省略，每次调用会自动生成新的 UUID。
       }):
           print(chunk, end="", flush=True)
       ```
     </TabItem>
   </Tabs>

   <Aside type="tip" title="使用非流式代理？">
     如果代理设置了 `streaming: false`，服务器会以单个 `text/plain` 响应返回完整回复 — 没有可供 `streamChatText` 解析的 `text-delta` 事件，因此它什么也不产出。下面的模式通过根据 `Content-Type` 分支来同时处理两种格式：

     <Tabs syncKey="lang">
       <TabItem label="TypeScript">
         ```typescript
         const res = await client.aiAgent.streamChat({
           assistant_id: aiAgentId,
           messages: [{ role: "user", content: "How do I reset my password?" }],
         })
         if (!res.ok) throw new Error(`HTTP ${res.status}: ${await res.text()}`)

         if ((res.headers.get("content-type") ?? "").includes("text/event-stream")) {
           // 流式代理 — 通过 SDK 辅助方法重新解析
           for await (const chunk of client.aiAgent.streamChatText({ /* 相同的请求体 */ })) {
             process.stdout.write(chunk)
           }
         } else {
           process.stdout.write(await res.text())   // 非流式代理
         }
         ```
       </TabItem>
       <TabItem label="Python">
         ```python
         res = client.ai_agent.stream_chat({
             "assistant_id": ai_agent_id,
             "messages": [{"role": "user", "content": "How do I reset my password?"}],
         })
         res.raise_for_status()

         if "text/event-stream" in res.headers.get("content-type", ""):
             for chunk in client.ai_agent.stream_chat_text({ "assistant_id": ai_agent_id, "messages": [...] }):
                 print(chunk, end="", flush=True)
         else:
             print(res.text)
         ```
       </TabItem>
     </Tabs>
   </Aside>

4. **维护对话历史（会话 ID）**

   在多次调用中传入相同的 `id`（必须是 UUID）以保持上下文：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       import { randomUUID } from "crypto"

       const sessionId = randomUUID()

       // 第一条消息
       await client.aiAgent.streamChat({
         assistant_id: aiAgentId,
         id: sessionId,
         messages: [{ role: "user", content: "What's your refund policy?" }],
       })

       // 后续 — 相同会话，AI 代理记得上下文
       await client.aiAgent.streamChat({
         assistant_id: aiAgentId,
         id: sessionId,
         messages: [{ role: "user", content: "How long does it take?" }],
       })
        ```
      </TabItem>
      <TabItem label="Python">
        ```python
        import uuid

        session_id = str(uuid.uuid4())

        # 第一条消息
        client.ai_agent.stream_chat({
            "assistant_id": ai_agent_id,
            "id": session_id,
            "messages": [{"role": "user", "content": "What's your refund policy?"}],
        })

        # 后续 — 相同会话，AI 代理记得上下文
        client.ai_agent.stream_chat({
            "assistant_id": ai_agent_id,
            "id": session_id,
            "messages": [{"role": "user", "content": "How long does it take?"}],
        })
       ```
     </TabItem>
   </Tabs>

</Steps>

## 2. 创建工作流并将其绑定到 AI 代理

<Steps>

1. **获取你的项目 ID**

   从 Imbrace 控制台 → Workflows 复制你的 Project ID；如果你的组织已有流程，也可以通过代码解析：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 方案 A — 从控制台复制后硬编码（推荐新组织使用）
       const projectId = "your_project_id"

       // 方案 B — 从已有流程解析（如果组织还没有任何流程则抛出异常）
       const projectId = await client.workflows.resolveProjectId()
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       # 方案 A — 从控制台复制后硬编码（推荐新组织使用）
       project_id = "your_project_id"

       # 方案 B — 从已有流程解析（如果组织还没有任何流程则抛出异常）
       project_id = client.workflows.resolve_project_id()
       ```
     </TabItem>
   </Tabs>

2. **创建新流程**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const flow = await client.workflows.createFlow({
         displayName: "CRM Update on New Lead",
         projectId,
       })
       console.log("Flow created:", flow.id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       flow = client.workflows.create_flow(
           display_name="CRM Update on New Lead",
           project_id=project_id,
       )
       print("Flow created:", flow["id"])
       ```
     </TabItem>
   </Tabs>

3. **添加 Webhook 触发器并发布流程**

   新创建的流程处于 **DRAFT** 状态，没有触发器 — Webhook URL 还不存在，所以 `triggerFlow` 会返回 404。先添加 Webhook 组件作为触发器，然后发布：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 设置 Webhook 组件作为流程的触发器
       await client.workflows.applyFlowOperation(flow.id, {
         type: "UPDATE_TRIGGER",
         request: {
           name: "trigger",
           type: "PIECE_TRIGGER",
           valid: true,
           displayName: "Webhook",
           settings: {
             pieceName: "@activepieces/piece-webhook",
             pieceVersion: "0.1.24",
             triggerName: "catch_webhook",
             input: { authType: "none" },
             propertySettings: {},
           },
         },
       })

       // 发布 — 流程状态变为 DISABLED → ENABLED，Webhook URL 变为可用
       await client.workflows.applyFlowOperation(flow.id, {
         type: "LOCK_AND_PUBLISH",
         request: {},
       })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       # 设置 Webhook 组件作为流程的触发器
       client.workflows.apply_flow_operation(flow["id"], {
           "type": "UPDATE_TRIGGER",
           "request": {
               "name": "trigger",
               "type": "PIECE_TRIGGER",
               "valid": True,
               "displayName": "Webhook",
               "settings": {
                   "pieceName": "@activepieces/piece-webhook",
                   "pieceVersion": "0.1.24",
                   "triggerName": "catch_webhook",
                   "input": {"authType": "none"},
                   "propertySettings": {},
               },
           },
       })

       # 发布 — DISABLED → ENABLED，Webhook URL 变为可用
       client.workflows.apply_flow_operation(flow["id"], {
           "type": "LOCK_AND_PUBLISH",
           "request": {},
       })
       ```
     </TabItem>
   </Tabs>

4. **手动触发流程并传入负载**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 触发后不等待结果（异步）
       await client.workflows.triggerFlow(flow.id, {
         contact_name: "Jane Smith",
         email: "jane@example.com",
       })

       // 同步触发 — 要让它实际返回数据而不超时，
       // 流程需要先通过 applyFlowOperation 的 ADD_ACTION 添加 "Return Response" 动作
       // （否则网关会等待 30 秒然后放弃）。
       const result = await client.workflows.triggerFlowSync(flow.id, {
         contact_name: "Jane Smith",
         email: "jane@example.com",
       })
       console.log("Flow result:", result)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       # 触发后不等待结果（异步）
       client.workflows.trigger_flow(flow["id"], {
           "contact_name": "Jane Smith",
           "email": "jane@example.com",
       })

       # 同步触发 — 要让它实际返回数据而不超时，
       # 流程需要先通过 apply_flow_operation 的 ADD_ACTION 添加 "Return Response" 动作
       # （否则网关会等待 30 秒然后放弃）。
       result = client.workflows.trigger_flow_sync(flow["id"], {
           "contact_name": "Jane Smith",
           "email": "jane@example.com",
       })
       print("Flow result:", result)
       ```
     </TabItem>
   </Tabs>

5. **将流程绑定到你的 AI 代理**

   在 Imbrace 仪表盘中打开你的 AI 代理，转到 **工具 → 工作流**，然后附加该流程。AI 代理将能够在对话中适当时触发它。

   或者，更新 AI 代理以按名称引用工作流：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       await client.chatAi.updateAiAgent(aiAgentId, {
         name: "Support Bot",
         workflow_name: "support_bot_v1",
         workflow_function_call: [{ flow_id: flow.id, description: "Update CRM on new lead" }],
       })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       client.chat_ai.update_ai_agent(ai_agent_id, {
           "name": "Support Bot",
           "workflow_name": "support_bot_v1",
           "workflow_function_call": [
               {"flow_id": flow["id"], "description": "Update CRM on new lead"}
           ],
       })
       ```
     </TabItem>
   </Tabs>

6. **查看运行历史**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const { data: runs } = await client.workflows.listRuns({
         flowId: flow.id,
         limit: 10,
       })
       for (const run of runs) {
         console.log(run.id, run.status, run.startTime)
       }
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       res = client.workflows.list_runs(flow_id=flow["id"], limit=10)
       for run in res.get("data", []):
           print(run["id"], run.get("status"), run.get("startTime"))
       ```
     </TabItem>
   </Tabs>

</Steps>

## 3. 管理知识中心并附加到 AI 代理

知识中心文件和文件夹位于 **data-board** 服务中（`client.boards`）。文件夹的 `_id` 就是你作为知识源传递给 AI 代理的值。

<Steps>

1. **创建文件夹**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const folder = await client.boards.createFolder({
         name: "Product Documentation",
         organization_id: process.env.IMBRACE_ORGANIZATION_ID,
         parent_id: "root",
       })
       console.log("Folder ID:", folder._id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       folder = client.boards.create_folder({
           "name": "Product Documentation",
           "organization_id": os.environ.get("IMBRACE_ORGANIZATION_ID"),
           "parent_id": "root",
       })
       print("Folder ID:", folder["_id"])
       ```
     </TabItem>
   </Tabs>

2. **上传文件到文件夹**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       import { readFileSync } from "fs"

       const fileBuffer = readFileSync("./docs/faq.pdf")
       const formData = new FormData()
       formData.append("file", new Blob([fileBuffer], { type: "application/pdf" }), "faq.pdf")
       formData.append("folder_id", folder._id)
       formData.append("organization_id", process.env.IMBRACE_ORGANIZATION_ID ?? "")

       const uploaded = await client.boards.uploadFile(formData)
       console.log("File uploaded:", uploaded.file_id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       from pathlib import Path

       path = Path("./docs/faq.pdf")
       files = {
           "file": (path.name, path.read_bytes(), "application/pdf"),
           "folder_id": (None, folder["_id"]),
           "organization_id": (None, os.environ.get("IMBRACE_ORGANIZATION_ID")),
       }
       uploaded = client.boards.upload_file(files)
       print("File uploaded:", uploaded.get("file_id") or uploaded.get("_id"))
       ```
     </TabItem>
   </Tabs>

3. **将文件夹附加到 AI 代理**

   在 `folder_ids` 中传入文件夹 `_id` — AI 代理会从该文件夹中的每个文件检索信息。使用 `board_ids` 附加一个 CRM 数据面板（其条目成为知识源 — 参见[资源 → 面板与条目](/zh-cn/sdk/databoard/#items)）。旧版 `knowledge_hubs` 字段已弃用。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       await client.chatAi.updateAiAgent(aiAgentId, {
         name: "Support Bot",
         workflow_name: "support_bot_v1",
         folder_ids: [folder._id],
         // board_ids: [boardId],  // 可选：附加 CRM 数据面板
       })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       client.chat_ai.update_ai_agent(ai_agent_id, {
           "name": "Support Bot",
           "workflow_name": "support_bot_v1",
           "folder_ids": [folder["_id"]],
           # "board_ids": [board_id],  # 可选：附加 CRM 数据面板
       })
       ```
     </TabItem>
   </Tabs>

4. **检查和管理文件夹与文件**

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       // 搜索文件夹
       const folders = await client.boards.searchFolders({ q: "Product" })

       // 获取文件夹及其内容
       const contents = await client.boards.getFolderContents(folder._id)
       console.log("Files:", contents.files?.length)

       // 重命名文件夹

       // 搜索文件夹中的文件
       const files = await client.boards.searchFiles({ folderId: folder._id })

       // 删除文件夹
       await client.boards.deleteFolders({ ids: [folder._id] })
       ```
     </TabItem>
     <TabItem label="Python">
       ```python

       folders = client.boards.search_folders(q="Product")

       # 获取文件夹及其内容
       contents = client.boards.get_folder_contents(folder["_id"])
       print("Files:", len(contents.get("files") or []))

       # 重命名文件夹
       client.boards.update_folder(folder["_id"], {"name": "Product Docs v2"})

       # 搜索文件夹中的文件
       files = client.boards.search_files(folder_id=folder["_id"])

       # 删除文件夹
       client.boards.delete_folders([folder["_id"]])
       ```
     </TabItem>
   </Tabs>

</Steps>

## 4. 管理数据面板与条目（CRM 管道）

<Steps>

1. **创建面板**

   面板是一个 CRM 管道 — 线索、交易、任务或任何结构化数据。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const board = await client.boards.create({
         name: "Sales Pipeline",
         description: "Track all active deals",
       })
       console.log("Board ID:", board._id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       board = client.boards.create(
           name="Sales Pipeline",
           description="Track all active deals",
       )
       print("Board ID:", board["_id"])
       ```
     </TabItem>
   </Tabs>

2. **添加自定义字段**

   字段类型包括 `ShortText`、`LongText`、`Number`、`Dropdown`、`Date`、`Checkbox` 等。`createField` 返回新创建的字段。要查看面板上的所有字段，请另外获取该面板。

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       await client.boards.createField(board._id, {
         name: "Company",
         type: "ShortText",
       })

       // 面板会自动创建一个标识符字段 — 获取面板以查看所有字段
       const boardWithFields = await client.boards.get(board._id) as any
       const identifierField = boardWithFields.fields?.find((f: any) => f.is_identifier)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       client.boards.create_field(board["_id"], {
           "name": "Company",
           "type": "ShortText",
       })

       # 获取面板以查看所有字段（包括自动创建的标识符字段）
       board_with_fields = client.boards.get(board["_id"])
       identifier_field = next(f for f in board_with_fields.get("fields", []) if f.get("is_identifier"))
       ```
     </TabItem>
   </Tabs>

3. **创建面板条目（记录）**

   条目使用 `{ fields: [{ board_field_id, value }] }` 格式：

   <Tabs syncKey="lang">
     <TabItem label="TypeScript">
       ```typescript
       const item = await client.boards.createItem(board._id, {
         fields: [
           { board_field_id: identifierField._id, value: "Acme Corp" },
         ],
       })
       console.log("Item ID:", item._id)
       ```
     </TabItem>
     <TabItem label="Python">
       ```python
       item = client.boards.create_item(board["_id"], {
           "fields": [
               {"board_field_id": identifier_field["_id"], "value": "Acme Corp"},
           ],
       })
       print("Item ID:", item["_id"])
       ```
