import { Tabs, TabItem } from "@astrojs/starlight/components";

Document AI 使用视觉模型（如 GPT-4o）从 PDF 和图片中提取结构化数据 — 发票、表单、收据、合同或任何带有可见文本的文档。

SDK 暴露四个命名空间：
- **`client.dociq`** — 把文档上传给 DocIQ：DocIQ 为每份文档匹配文档模型，完成提取，并在该模型的数据表上写入一条记录
- **`client.chatAi` / `client.chat_ai`** — 直接文档处理和模型列表
- **`client.documentModels` / `client.document_models`** — DocIQ 的文档模型：要提取哪些字段、结果写入哪个数据表、分类和提取设置
- **`client.documentAi` / `client.document_ai`** — 基于代理的文档处理、排队任务、代理增删改查和端到端编排

首先初始化客户端（参见[安装](/zh-cn/sdk/installation/)或[快速入门](/zh-cn/sdk/quick-start/)）。

## `client.dociq` — 上传与提取（DocIQ）

这是把文档交给 DocIQ 的常用方式。上传文件并提交：DocIQ 会选择合适的文档模型，提取字段，并在该模型的数据表上写入一条记录。请先用 [`client.documentModels`](#clientdocumentmodels--document-models-dociq) 设置好模型。

### 上传并提交

用 `client.boards.uploadBoardFile()` 上传，再把返回的 `url` 传给 `ingest()`。每次调用接受 1 到 5 个文件，并立即为每个文件返回一个 submission；读取过程在后台进行。

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const form = new FormData();
form.append("file", new Blob([pdfBytes], { type: "application/pdf" }), "invoice.pdf");
const { url } = await client.boards.uploadBoardFile(form);

const { submissions } = await client.dociq.ingest({
  files: [{ url, mime_type: "application/pdf", name: "invoice.pdf" }],
});
const submissionId = submissions[0].id;
```
</TabItem>
<TabItem label="Python">
```python
with open("invoice.pdf", "rb") as f:
    url = client.boards.upload_board_file({"file": ("invoice.pdf", f, "application/pdf")})["url"]

res = client.dociq.ingest([{"url": url, "mime_type": "application/pdf", "name": "invoice.pdf"}])
submission_id = res["submissions"][0]["id"]
```
</TabItem>
</Tabs>

| 选项 | 类型 | 含义 |
|---|---|---|
| `files` | `{ url, mime_type, name? }[]` | 1 到 5 个文件。`url` 为上传返回的值，或一个绝对 URL |
| `assistant_id` | string | 使用该 DocIQ 助手的模型读取，而不是默认模型 |
| `source` | `{ channel?, conversation_id? }` | 文件并非上传而来时的来源（例如某个消息渠道），按原样保存 |

写入数据表时以调用者的身份执行，因此请求必须带有用户：不带用户的调用会被拒绝并返回 400。组织需要开通文档模型功能。

### 跟踪 submission

submission 有两种状态。`status` 表示读取进度：`pending`、`running`，然后是 `succeeded`、`failed` 或 `canceled`。`outcome` 表示写入数据表的结果：`saved`、`no_schema`（没有匹配的模型）、`model_created`、`failed`，尚未执行时为 `pending`。

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
let sub = await client.dociq.getSubmission(submissionId);
while (sub.status === "pending" || sub.status === "running" || (sub.status === "succeeded" && sub.outcome === "pending")) {
  await new Promise(r => setTimeout(r, 5000));
  sub = await client.dociq.getSubmission(submissionId);
}

if (sub.outcome === "saved") {
  console.log(sub.documentModelName, sub.boardId, sub.boardItemId);
  console.log(sub.extractedData);  // 提取出的记录
  console.log(sub.extractedMeta);  // 每个字段：置信度、状态、读取位置
}
```
</TabItem>
<TabItem label="Python">
```python
import time

sub = client.dociq.get_submission(submission_id)
while sub["status"] in ("pending", "running") or (sub["status"] == "succeeded" and sub["outcome"] == "pending"):
    time.sleep(5)
    sub = client.dociq.get_submission(submission_id)

if sub["outcome"] == "saved":
    print(sub["documentModelName"], sub["boardId"], sub["boardItemId"])
    print(sub["extractedData"])  # 提取出的记录
    print(sub["extractedMeta"])  # 每个字段：置信度、状态、读取位置
```
</TabItem>
</Tabs>

一个文件中包含多份文档时（例如一个 PDF 里有三张发票）会被拆分：`documents` 列出每份文档及其对应的模型和数据表，`boardItemId` 为第一条记录。失败的 submission 带有 `error` 和 `processLog`。`getSubmissionByFile()` 按结果表中显示的 File ID（例如 `INV-2026-001`）查找最新的 submission。

## `client.documentModels` — 文档模型（DocIQ）

文档模型列出要从某一类文档中提取的字段。每个模型对应一个数据表，用它读取的每份文档都会成为该数据表上的一条记录。[`client.dociq`](#clientdociq--upload-and-extract-dociq) 会为每份文档自动选择模型；使用 `documentAi.process()` 时，则需要将数据表作为 `boardId` 传入。

每个模型属于一个产品，即它的 `type`：`"DocumentAI"`（DocIQ，默认）或 `"Comms"`（CommsIQ）。`type` 在创建模型时设定，之后不会改变。

### 创建模型及其数据表

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const model = await client.documentModels.create({
  name: "Invoice",
  attributes: [
    { name: "Invoice number", type: "ShortText" },
    { name: "Total", type: "Number" },
    { name: "Date", type: "Date" },
  ],
});

// 创建模型不会创建数据表：需要单独开通。
const [{ board_id }] = await client.documentModels.provisionBoards({
  schemas: [{ schema_id: model.id, data_board_name: "Invoices" }],
});

const result = await client.documentAi.process({
  url: "https://example.com/invoice.pdf",
  organizationId: "org_xxx",
  modelName: "gpt-4o",
  boardId: board_id,
});
```
</TabItem>
<TabItem label="Python">
```python
model = client.document_models.create({
    "name": "Invoice",
    "attributes": [
        {"name": "Invoice number", "type": "ShortText"},
        {"name": "Total", "type": "Number"},
        {"name": "Date", "type": "Date"},
    ],
})

# 创建模型不会创建数据表：需要单独开通。
board_id = client.document_models.provision_boards(
    {"schemas": [{"schema_id": model["id"], "data_board_name": "Invoices"}]}
)[0]["board_id"]

result = client.document_ai.process(
    url="https://example.com/invoice.pdf",
    organization_id="org_xxx",
    model_name="gpt-4o",
    boardId=board_id,
)
```
</TabItem>
</Tabs>

创建时的 `agents` 和 `databoards` 已弃用：后端会忽略它们。请使用 `provisionBoards`（传入 `assistant_id` 可同时关联助手）。

## 排队提取与 webhook

`client.documentAi.process()` 和 `client.chatAi.processDocument()` 调用同一个端点。服务器可能会把文档放入队列，而不是立即提取；默认情况下，超过 20 页的 PDF 会被排队。此时调用会立即返回（HTTP 202），带有 `job_id`，但没有 `data`。

- 传入 `sync: true`，始终立即提取并返回 `data`。
- 传入 `sync: false`，始终排队。
- 用 `getJob()` 跟踪排队的任务。提取出的字段不在任务里：当 `status` 为 `done` 时，它们位于任务所指的数据表行的 `RawResult` 字段中。

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const res = await client.documentAi.process({
  url: "https://example.com/contract.pdf",
  organizationId: "org_xxx",
  modelName: "gpt-4o",
  boardId: board_id,
});

if (res.job_id) {
  let job = await client.documentAi.getJob(res.job_id);
  while (job.status === "pending" || job.status === "in_progress") {
    await new Promise(r => setTimeout(r, 5000));
    job = await client.documentAi.getJob(res.job_id);
  }
  if (job.status === "done" && job.board_id && job.board_item_id) {
    const row = await client.boards.getItem(job.board_id, job.board_item_id);
  }
} else {
  console.log(res.data);
}
```
</TabItem>
<TabItem label="Python">
```python
import time

res = client.document_ai.process(
    url="https://example.com/contract.pdf",
    organization_id="org_xxx",
    model_name="gpt-4o",
    boardId=board_id,
)

if res.get("job_id"):
    job = client.document_ai.get_job(res["job_id"])
    while job["status"] in ("pending", "in_progress"):
        time.sleep(5)
        job = client.document_ai.get_job(res["job_id"])
    if job["status"] == "done":
        row = client.boards.get_item(job["board_id"], job["board_item_id"])
else:
    print(res["data"])
```
</TabItem>
</Tabs>

任务的 `status` 为 `pending`、`in_progress`、`done` 或 `error`。任务记录默认一天后过期，之后 `getJob()` 会返回 404 错误；数据表行仍会保留。

除了轮询，也可以传入 `webhookUrl`。提取完成时，无论成功还是失败、立即处理还是排队，服务器都会向它 POST 结果，并原样带回你发送的 `meta`：

```json
{
  "event": "document_ai.completed",
  "status": "completed",
  "job_id": "…",
  "board_id": "…",
  "board_item_id": "…",
  "data": { },
  "meta": { "ref": "r1" },
  "error": null
}
```

文档被立即处理时，`job_id` 为 `null`。`status` 为 `"completed"` 或 `"error"`。

## OCR 置信度

启用 `enableOcrConfidence` 后，OCR 引擎会与视觉模型一起读取文档，每个提取字段都会附带 `{ value, box, confidence }`。`confidenceThreshold`（0–1）会丢弃置信度更低的字段。`ocrEngine` 选择引擎：`"paddleocr-vl"`（仅文本）、`"chandra"`（带框的版面）或 `"easyocr"`（带框的文本块）；省略时使用服务器默认引擎。

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const result = await client.documentAi.process({
  url: "https://example.com/scan.png",
  organizationId: "org_xxx",
  modelName: "gpt-4o",
  boardId: board_id,
  sync: true,
  enableOcrConfidence: true,
  confidenceThreshold: 0.6,
  ocrEngine: "easyocr",
});
```
</TabItem>
<TabItem label="Python">
```python
result = client.document_ai.process(
    url="https://example.com/scan.png",
    organization_id="org_xxx",
    model_name="gpt-4o",
    boardId=board_id,
    sync=True,
    enableOcrConfidence=True,
    confidenceThreshold=0.6,
    ocrEngine="easyocr",
)
```
</TabItem>
</Tabs>

`client.document_ai.process()` 会把额外的关键字参数原样发送给服务器，因此它们保持 camelCase 名称。`client.chat_ai.process_document()` 则使用 snake_case（`enable_ocr_confidence=True`）。

## `client.documentAi` — 代理增删改查

### 列出代理

<Tabs syncKey="lang">

// 所有代理
const agents = await client.documentAi.listAgents();

## `client.documentAi` — 完整创建（编排器）

端到端 Document AI 代理创建（iMBRACE webapp 所做的）：创建一个带有提取 schema 的面板，然后创建一个链接到该面板的 UseCase + AI 代理。

<Tabs syncKey="lang">
<TabItem label="TypeScript">
```typescript
const result = await client.documentAi.createFull({
  name: "Invoice Extractor",
  instructions: "Extract invoice fields. Dates as YYYY-MM-DD.",
  schemaFields: [
    { name: "invoice_number", type: "ShortText", description: "Invoice ID" },
    { name: "total",          type: "Number",    description: "Total amount" },
    { name: "date",           type: "Date",      description: "Invoice date" },
  ],
  modelId: "gpt-4o",
  providerId: "system",
});

console.log(result.board_id);     // "brd_xxx"
console.log(result.ai_agent_id);  // 所创建的 AI 代理的 UUID
console.log(result.usecase_id);   // 所创建的 UseCase 的 UUID
```
</TabItem>
<TabItem label="Python">
```python
result = client.document_ai.create_full(
    name="Invoice Extractor",
    instructions="Extract invoice fields. Dates as YYYY-MM-DD.",
    schema_fields=[
        {"name": "invoice_number", "type": "ShortText", "description": "Invoice ID"},
        {"name": "total",          "type": "Number",    "description": "Total amount"},
        {"name": "date",           "type": "Date",      "description": "Invoice date"},
    ],
    model_id="gpt-4o",
    provider_id="system",
)

print(result["board_id"])      # "brd_xxx"
print(result["ai_agent_id"])   # 所创建的 AI 代理的 UUID
```
</TabItem>
