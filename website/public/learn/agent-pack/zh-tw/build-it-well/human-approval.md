# 人工核准

每個重要的建置都會有一個時刻，需要有人先點頭同意，某件事才能送出去。決策本身一直都是同一種東西；一個人在哪裡做出這個決策，則會因使用案例而不同。

## 決策是一回事，介面是另一回事

決策的部分，會根據背後的紀錄推算出該發生什麼事，在還沒有人做出決定時拒絕繼續進行，並且記錄下是誰做的決定、決定了什麼，以及什麼時候做的。這個部分不會因建置不同而改變。

介面——也就是一個人實際在哪裡、用什麼方式做出這個決策——則是一項設計選擇，依使用案例而定，取決於這個人原本就在哪裡工作，以及建置在等待期間該有什麼樣的行為。

## 五個可以做出決策的地方

| 介面 | 運作方式 | 適用時機 |
|---|---|---|
| **紀錄上的一個欄位** | 一個人在「數據表」（board）或清單上，把狀態欄位切換到另一個值；狀態一改變，下一步就會自動觸發 | 審核者原本就每天使用那個數據表工作。不需要客製介面，也是目前為止最常見的一種介面 |
| **真正等待的暫停點** | 建置會真的把執行暫停下來，直到有人解決它為止，而不是不斷輪詢或用猜的 | 流程在有人採取行動之前，完全不能繼續 |
| **一次性連結** | 一個經過簽署的連結，每種可能的結果各一個；點開連結會顯示詳細內容，在上面確認就會寫入決策 | 審核者完全在別的地方，為他們建一個入口網站太大費周章 |
| **聊天室裡的核准卡片** | 建置會在審核者原本就在用的頻道裡，貼出一則附按鈕的訊息；一點按鈕，執行就會繼續 | 審核者原本就活躍在那個頻道裡 |
| **對話中的一則指令** | 一位經過驗證身分的人輸入核准，並指名特定項目；系統會把這個核准記錄在該項目上 | 審核者原本就在跟一個代理人對話，而且該頻道能驗證對方身分 |

這五種方式，最後都會走到同一個地方：一筆與特定項目綁定、記錄了是誰在什麼時候做出決定的紀錄。

記錄決策並不是最後一步。不論用的是哪一種介面，一旦決策到位，流程就會自己接著往下走——完成它原本在等待的工作，或是把結果告訴當初提出請求的人——不需要任何人發現後再回來追問一次。

哪些介面可以使用，取決於你的安裝環境與版本；你的 iMBrace 聯絡窗口可以幫你確認。記錄上的欄位是使用最廣泛、也最適合作為起點的方式。不論你選擇哪一種介面，在依賴它之前，先以審核者的身分親自走一遍整個流程：對方收到通知、打開項目、記錄決策。

## 一個經過驗證的組合：用數據表欄位讓暫停的工作流恢復執行

當流程必須真的等待，而審核者又是在數據表上工作時，就把前兩種介面組合起來使用。工作流會建立一項任務（Todos 步驟），通知審核者——例如透過電子郵件，附上指向該筆紀錄的連結，而不是可以直接做決定的連結——接著暫停等待。審核者在該筆紀錄的一個單選欄位中，選擇核准或拒絕。綁定在這個欄位上的一則自動化，會讓暫停的任務恢復執行。之後由工作流——而不是那次編輯本身——寫入結果，因此決策永遠只有一個寫入者。

直接通知審核者。一項等待中的任務，只有在審核者知道它存在時才會往下走，所以附上紀錄連結的通知訊息，是這個模式中必要的一步，而不是額外加上去的。

## 不能通融的規則

**在聊天室裡友善地打一聲「好」，本身並不算是一項決策。** 那只是流程控制——它可能只是讓對話繼續下去——但單靠它，並不會留下任何持久的紀錄，讓日後有人能夠指出：這件事在這個時間，由這個人核准。

上面提到的指令介面，並不是這條規則的例外。它正是讓一則聊天訊息真正算作決策的原因：系統會把它擷取成一筆針對特定項目、附有經過驗證發送者的結構化紀錄，而不是任由它留在對話紀錄裡。一句沒有指名任何特定項目的「好」，完全不會被當作決策接受。

還有兩條值得牢記的規則：

- **關卡自己算出答案。** 它會根據背後的紀錄重新計算結果，而不是相信同一次互動中剛被告知的數字。一個只相信別人告訴它什麼的關卡，會很樂意核准一個錯誤的數字。
- **沒有決策，就沒有輸出。** 不是預設放行，也不是過一段時間逾時就自動放行。只要還沒有人做出決定，就不會有任何東西送出去。

## 讓關卡真正守住的四個細節

- **數據表的編輯，要到按下「儲存」（Save）之後才會生效。** 請從已儲存的狀態測試這個關卡，並在給審核者的操作說明中，加入「按下『儲存』」這一步。
- **決策連結一律先顯示內容，只有在確認之後才會執行動作。** 不論是人、郵件掃描程式，還是預覽功能打開了這個連結，都絕不能單憑這樣就記錄一筆決策。決策連結只能寄送給審核者本人，而且連結本身、以及任何可能用來做出決策的識別碼，都不能出現在紀錄裡。
- **代理人絕不能有寫入決策的能力。** 用來記錄決策的欄位，應該在紀錄建立時就設定好起始值，並拒絕代理人之後對它做任何寫入——只給代理人範圍狹窄、碰不到這些欄位的工具。
- **「尚未有結果」絕不能被看成「通過」。** 一項還沒執行，或執行失敗的檢查，會讓紀錄看起來和真正通過的一模一樣。請在每一筆紀錄上都蓋上結果戳記，包括乾淨無虞的那些，並讓之後每一個步驟都等待這個戳記、沒有它就拒絕繼續。

## 證明關卡確實有接上線路，而不只是擺在那裡

一個控制點的好壞，取決於它究竟綁定了什麼。請確認狀態欄位在它能取的每一個值上，都會觸發一個真正的自動化，而不只是你預期會用到的那幾個值。

把這個介面接到真正依賴它的東西上，並在宣告核准步驟完成之前，把整條路徑從頭到尾實際跑過一遍——包括「還沒有人做出決定」這個情況。
