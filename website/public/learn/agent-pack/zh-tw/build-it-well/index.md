# 建置得好

一場展示證明的是某個東西能運作一次。建置得好，代表它能持續運作：使用真實資料、承受真實負載、有真人確實參與其中，而且不需要靠任何人刻意記得要小心。

這與寫更多程式碼無關。讓一個建置成果穩固的，大多是你在動手寫任何東西之前所做的設計選擇：你用哪些元件組裝它、由誰在哪個環節簽核、哪些工作交給平台本身的能力而非自訂程式碼，以及哪些內容絕不離開建置本身的設定。

## 八大原則，一句話說明

1. **溯源性（Provenance）**——答案中的每一個數字都能追溯回它的出處，否則答案會直接說明查無此資料。
2. **確定性（Determinism）**——由 AI 判斷該套用哪一條規則；規則本身以資料的形式存在，可供人員編輯；運算則始終以相同、可靠的方式進行。
3. **模組化（Modularity）**——建置成果是由各自只做一件事、且有清楚介接規範的元件組裝而成，而不是一團龐大糾結的自訂邏輯。
4. **領域無關的核心（Domain-free cores）**——可重複使用的邏輯不帶有任何客戶名稱或特定業務細節；所有屬於單一企業的特有內容，都以設定的形式帶入。
5. **人為治理（Human governance）**——一個真正的決定是被記錄下來的事實——誰決定的、決定了什麼、何時決定的——而不是在聊天視窗裡打一個友善的「好」。
6. **原生優先（Native-first）**——在寫任何自訂程式碼之前，先使用平台本身已經提供的功能；建置成果中不應該存放任何登入憑證。
7. **可維運性（Operability）**——建置成果可以被重設、測試，並由他人獨立查核，而不是只能由建置者本人執行一次。
8. **安全與主權（Security and sovereignty）**——憑證、密鑰與敏感資料只留在設定中，絕不進入建置本身的邏輯。
