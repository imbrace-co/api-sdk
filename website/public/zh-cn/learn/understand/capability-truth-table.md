# iMBrace 今天能做什么

下面每一行都是 iMBrace 今天就能用的能力，都对照真实页面或产品本身核实过——不是计划，也不是路线图。凡标注“（企业版部署）”的行，该能力属于这一类部署；其余能力均为通用可用。版本与定价问题请联系你的 iMBrace 联系人。

## 触达客户与员工

| 你可以做什么 | 在哪里查看 |
|---|---|
| 通过 WhatsApp、Facebook Messenger、Instagram、LINE、微信、电子邮件，或你自己网站上的网页聊天挂件与客户交流——所有渠道都汇总在同一个共享收件箱中 | 产品内（“对话”，Conversations） |
| 每一段对话都会被追踪各自的状态——在线、逾期、待客服介入、待处理或已结束——让你的团队始终清楚哪些对话需要回复 | 产品内（“对话”） |
| 按团队拆分对话，可以选择先到先得模式，也可以让团队内所有人自由加入 | 产品内（“团队管理”，Teams；“对话”） |

## 智能体与知识

| 你可以做什么 | 在哪里查看 |
|---|---|
| 构建一个拥有自己的个性、语气和核心任务的 AI 智能体，并为它提供作答所需的参考资料——支持 PDF、Word、纯文本、CSV 或 Excel 文件 | 产品内（“AI智能助手”，AgentIQ） |
| 让智能体直接调用组织中已有的知识，而不必重新上传 | 产品内（“AI智能助手”；“知识模块”，Knowledge） |
| 将某个知识文件夹或数据表限定给指定团队，只有这些团队的成员才能看到其中的内容 | 产品内（“知识模块”） |
| 在较长的多轮往来中保持智能体的上下文：它会记住同一对话中之前的内容 | 产品内（“AI智能助手”；高级设置） |
| 设置一个编排智能体，把任务的一部分交给一个或多个专门的子智能体处理 | 产品内（“创建您的AI智能助手 - 协调者”，Create Your AI - Orchestrator） |
| 在自动化工作流程内部调用智能体或文档提取步骤，让 AI 步骤成为更大流程的一部分，而不是一段独立的对话 | 产品内（工作流程，Workflows；AI 智能体技能） |

## 文档

| 你可以做什么 | 在哪里查看 |
|---|---|
| 把 PDF 或图片——发票、表单、收据、合同、名片等等——转换成结构化记录，使用的是能读懂版面布局的模型，而不是固定模板 | https://engineer.imbrace.co/zh-cn/sdk/document-ai |
| 把提取规则设置一次，保存为“文档模型”，之后同类型的每份文档都能重复使用；版本历史会显示它是如何变化的 | 产品内（“文档模块”，DocIQ；“文档模型”，Document Models） |
| 把提取结果直接发送到数据表，映射到你选择的列，如果需要，还可以同时发送到多张表 | 产品内（“文档模块”） |
| 告诉“文档模块”你的文档使用的语言，以提高提取准确度，手写文档也包括在内 | 产品内（“文档模块”；“设置”，Settings） |
| 把参考资料以多种格式上传到知识文件夹——PDF、Word、PowerPoint、Excel、CSV、视频或图片文件均可 | 产品内（“知识模块”） |
| 限定哪些团队可以使用某个文档模型，方式与限定知识文件夹相同 | 产品内（“文档模块”；“文档模型”） |

## 数据与工作流程

| 你可以做什么 | 在哪里查看 |
|---|---|
| 把结构化记录保存在一张共享数据表上，供每个工作流程、智能体和员工读写 | 产品内（“知识模块”；“数据表”，DataIQ） |
| 通过已连接渠道收到的消息、一个定时计划，或数据表记录的变化——新建、删除，或指定字段被更新——来启动一个工作流程 | 产品内（工作流程；“流程运营模块”，FlowOps） |
| 在工作流程内部通过预先构建好的连接器对接外部系统——iMBrace 原生集成了100多种服务，从 CRM 到电子表格再到工单系统 | 产品内（“应用整合”，Integrations） |
| 把连接器的凭证保存在组织自己的存储中，与工作流程本身分开，这样共享或导出的工作流程定义中都不会带有密钥 | https://engineer.imbrace.co/zh-cn/sdk/workflows |
| 在重要的决策点暂停工作流程，等待指定的人做决定，需要多久就等多久，然后自动继续运行，并记录下是谁做了决定、决定了什么、以及何时决定 | 产品内（工作流程；“数据管理自动化”，Board Automation） |

## 访问与治理

| 你可以做什么 | 在哪里查看 |
|---|---|
| 把知识文件夹或数据表限定给指定团队，让每个人只能看到自己所属的团队 | 产品内（“团队管理”；“访问控制”，Access Control） |
| 按团队内的角色设置成员权限——例如团队管理员与代表的区别 | 产品内（“团队管理”） |
| 把记录中的单个字段限定给特定角色，让同一张表对不同的读者显示不同的详细程度（企业版部署） | 产品内（“访问控制”） |
| 回顾整个平台的活动记录——登录、文件上传、渠道变更，以及数据表的变更——每一项都有时间戳，如果是某人操作的，还会记录到本人名下 | 产品内（“审计记录”，Audit Log） |
| 把活动记录延伸到 AI 智能体的操作（企业版部署） | 产品内（“审计记录”） |
| 访问规则由平台自身的权限检查强制执行，而不是靠写进提示词里的任何内容 | 产品本身 |
